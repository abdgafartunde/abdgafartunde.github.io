# abdgafartunde.github.io

Source code for the personal academic website of **Abd'gafar Tunde Tiamiyu**, hosted at [abdgafartunde.github.io](https://abdgafartunde.github.io).

Built with [Jekyll](https://jekyllrb.com/) and [GitHub Pages](https://pages.github.com/).

## About

Postdoctoral Researcher in Computational and Applied Mathematics at Jilin University. Research areas:
- Inverse problems and regularisation theory (linear and nonlinear)
- Computational imaging: EIT, CT, MRI, ultrasound, seismic FWI
- Scientific machine learning and physics-informed neural networks
- Numerical methods for PDEs and large-scale optimisation

## Local Development

```bash
git clone https://github.com/abdgafartunde/abdgafartunde.github.io.git
cd abdgafartunde.github.io
bundle install
bundle exec jekyll serve --livereload
```

Requires Ruby 3.4 (see `.ruby-version`) and Bundler. Open `http://localhost:4000` in your browser. GitHub Actions uses the pinned Jekyll engine and the three configured plugins directly.

To preview posts that are scheduled for a future date, add `--future`:

```bash
bundle exec jekyll serve --livereload --future
```

## Publishing

Every push to `master` builds the site and deploys it to GitHub Pages (`.github/workflows/pages.yml`). Posts dated in the future stay hidden; a daily build at 00:07 China Standard Time publishes each post on the date in its front matter.

The automatically updated RSS/Atom feed at `/feed.xml` remains available through feed-reader autodiscovery, without a visible subscription link. Each published article also gets its own 1200 × 630 PNG sharing card, generated from its title, topic, date and author after the Jekyll build. Open Graph, X/Twitter and JSON-LD metadata all point to the article's card. New posts receive cards automatically; the default website image remains in use on other pages. An explicit `image` value in a post's front matter overrides the generated card; `image_alt` can supply its description. For a custom image, optionally specify its actual `image_width` and `image_height`; dimensions are omitted when unknown.

Private drafts in `_planning/` are ignored by Git and excluded from the website. Publish a reviewed draft by moving it into `_posts/` with its intended publication date.

Cards are generated by `_tools/generate-social-images.mjs` using the bundled, unmodified Inter font from [Google Fonts](https://github.com/google/fonts/tree/main/ofl/inter), licensed under the SIL Open Font License included in `_tools/fonts/OFL.txt`. They are typographic graphics, without generated research imagery. To preview their output locally, build the site, then run `npm run build:social-images`; the PNG files appear under `_site/assets/images/social/`.

`CV.pdf` is compiled from `CV.tex` during every deployment, so edit `CV.tex` and push; you do not need to commit the PDF. Compilation can fall back to the live CV, but both paths must pass PDF validation before the file replaces the destination. To see the CV in a local preview, run `latexmk -pdf CV.tex` first.

Write inline math as `$$x$$`, not `$x$`. Kramdown only protects math inside `$$`, so single-dollar math loses backslash escapes such as `\{` and `\|`. A `$$` block on its own lines is displayed; `$$` inside a sentence is inline.

## Automated website checks

Every deployment and pull request validates the generated site before publication. A failing check stops deployment and leaves the current live site available. The checks cover internal page links and heading anchors, image and script references, duplicate IDs, HTML structure, self-canonical and sharing metadata, Atom feed parsing and entry targets, PDF integrity, private-file exclusions, and structural accessibility issues such as missing image descriptions and unlabelled controls. Removing the main landmark cannot bypass the audit.

To run locally with Node.js 24 or newer and `pdfinfo` (Poppler, installed automatically in CI):

```bash
npm ci
npm test
latexmk -pdf CV.tex
JEKYLL_ENV=production bundle exec jekyll build
npm run build:social-images
npm run check:site
```

The checker scans every generated HTML page without a fixed article count. External websites are not deployment gates: rate limits and temporary third-party outages should not block publishing. The `/ertkit/` documentation is also excluded from local link resolution because its own repository deploys it separately.

Accessibility checks use axe-core with JSDOM and cover document structure; they do not measure rendered color contrast, responsive layout or the quality of alternative text. Keep reviewing those in a browser after design changes. Node dependencies and checking tools are excluded from the published site.
